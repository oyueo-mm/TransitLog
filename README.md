# TransitLog

지하철·버스 탑승을 **5~10초 안에** 기록하고, 쌓인 기록으로 착석률·이동 시간을 분석하는 개인용 모바일 우선 PWA입니다.
Samsung Notes 에 날짜별로 적던 기록을 대체하기 위해 만들었습니다.

### 시간 입력과 하루 기록

- 모든 시각 입력은 `오전/오후 | 시 | 분` 세로 휠을 사용합니다. 터치 스와이프, 마우스 스크롤, 방향키로 1분 단위까지 선택할 수 있으며 선택한 값은 진하게 표시됩니다.
- 하루 기록의 집 출발·학교 도착·학교 출발·귀가 시간은 접힌 상태로 시작합니다. 시간 또는 `시간 입력 +`를 누르면 편집기가 열리고, `완료`로 저장하면 다시 접힙니다. `취소`는 변경 내용을 버립니다.
- 이동 타임라인에서 `1시간 단위`, `30분 단위`, `10분 단위`를 선택하면 해당 간격의 시간 눈금을 볼 수 있습니다. 그래프는 가로로 스크롤되며 실제 기록 좌표는 분 단위 정확도를 유지합니다.
- 관찰·놓침 기록은 이동 목록과 타임라인에 남지만 진행 중 탑승으로 표시되지 않습니다. 이전 백업에 진행 중 값이 남아 있어도 동일하게 처리합니다. IndexedDB 스키마와 `HH:mm` 저장 형식은 유지됩니다.
- 빠른 기록에서 하차 예정역을 정해 두었다면 `하차` 한 번으로 현재 시각과 예정역을 저장합니다. 좌석 정보와 변화 내역은 그대로 유지하며, 예정역이 없을 때만 하차 입력 화면이 열립니다. 완료 후에도 오늘의 이동 기록을 눌러 시각·역·좌석을 수정할 수 있습니다.

**접속 주소: <https://oyueo-mm.github.io/TransitLog/>** (GitHub Pages, 누구나 열 수 있는 공개 앱입니다)

- React + TypeScript + Vite, 서버·로그인 없음, 오프라인 사용 가능
- Android 스마트폰(홈 화면에 설치)과 Windows PC(브라우저)에서 사용

> ## ⚠️ 먼저 알아 둘 것: 기록은 기기마다 따로 저장됩니다
>
> - 모든 기록은 **지금 쓰는 기기·브라우저 안(IndexedDB)에만** 저장됩니다. 서버로 전송되지 않고, 이 사이트를 만든 사람도 볼 수 없습니다.
> - **휴대폰과 PC의 기록은 자동으로 합쳐지지 않습니다.** 같은 주소를 열어도 기기마다 빈 상태에서 시작합니다.
> - 브라우저 데이터를 지우거나, 앱을 삭제하거나, 기기를 바꾸면 **백업이 없는 기록은 복구할 수 없습니다.**
> - 그래서 **정기적으로 `설정·백업 → JSON 백업 파일 저장`** 을 눌러 파일을 보관해 주세요(드라이브·메일 등). 7일 넘게 백업이 없으면 오늘 화면 위에 알림이 뜹니다.
> - 다른 기기로 옮길 때는 백업 파일을 새 기기의 `설정·백업 → 백업 파일에서 복원`으로 불러옵니다. 복원은 기존 기록을 덮어쓰지 않는 **병합**이 기본입니다.

## 사용 방법

### 설치
- **Android(Chrome)**: 주소를 열고 메뉴 ⋮ → **홈 화면에 추가 / 앱 설치**. 설치하면 앱처럼 실행되고 비행기 모드에서도 열립니다.
- **Windows(Chrome·Edge)**: 주소창 오른쪽의 설치 아이콘(⊕) → **설치**. 설치하지 않고 브라우저 탭으로 써도 됩니다.
- 처음 한 번은 인터넷이 연결된 상태로 열어야 오프라인용 파일이 저장됩니다.

### 매일 쓰는 흐름
1. **빠른 기록** 탭 → 자주 타는 경로를 누른다(처음에는 노선·역을 입력하거나 칩에서 고른다).
2. **지금 좌석 상태**(서서/앉아서)와 필요하면 혼잡도를 고른다. 건너뛰면 *미기록*으로 저장됩니다.
3. **지금 탑승**을 누른다. 탑승 중에는 `앉았다`/`일어섰다`로 좌석 변화를, 내릴 때 `하차`를 누른다.
4. **오늘** 탭에서 집 출발·학교 도착·귀가 시각을 기록하고, **캘린더**에서 지난 날짜를 보거나 수정한다.
5. **통계** 탭에서 착석률 등을 확인한다.

### 기존 Samsung Notes 기록 옮기기
`설정·백업 → PDF 가져오기` → PDF 선택 → 미리보기에서 원문과 변환 결과를 비교·수정 → 승인. 자세한 처리 방식은 아래 *기존 노트 가져오기*를 참고하세요. 원본 PDF는 기기 밖으로 나가지 않으며 저장되지도 않습니다.

## 주요 기능

| 화면 | 내용 |
| --- | --- |
| 오늘의 기록 | 오늘의 이동 타임라인(승차 시각순), 집 출발·학교 도착·학교 출발·귀가 시각, 등교/하교 전체 이동 시간과 **개별 탑승 시간 합계를 구분**해 표시 |
| 빠른 기록 | 자주 타는 경로 한 번 선택 → 좌석 상태 선택 → **지금 탑승**. 탑승 중에는 `앉았다/일어섰다/하차` 버튼으로 시각을 자동 기록 |

| 통계 | 날짜·주·월별 탑승 횟수, 노선·구간별 이용, 요일·시간대·행선지·칸·칸-문별 착석률, 혼잡도 분포, 버스/지하철 비교 |
| 설정·백업 | JSON 백업/복원(병합·교체), CSV 내보내기, 저장소 보호 요청, 경로 관리, 전체 삭제 |
| 가져오기 | Samsung Notes PDF(또는 텍스트)를 분석 → **원문과 변환 결과를 비교·수정** → 승인한 것만 저장 |

### 하루 이동 타임라인 (오늘의 기록 · 캘린더의 날짜 화면)

이동 기록 목록 바로 아래에 그날의 탑승을 00:00~24:00 가로축 막대그래프로 보여 줍니다.

- 막대의 위치·길이는 승·하차 시각에 정확히 비례합니다. 노선별 행으로 나뉘고, 같은 노선을 여러 번 타거나 시간이 겹쳐도 모두 별도 막대(겹치면 아래 줄)로 그립니다.
- 좌석 상태는 **색이 아니라 모양**으로 구분합니다: 앉아서(진한 채움) · 서서(사선 줄무늬) · 좌석 미확인(점선 빈 막대). 좌석 이벤트 시각에서 막대가 나뉘고, 일어섬 이후는 다시 ‘서서’가 됩니다. 범례가 함께 표시됩니다.
- 기록되지 않은 값은 추정하지 않습니다: 탑승 시 좌석이 없거나 ‘좌석 변화 기록 완결’이 확인되지 않은 구간은 ‘미확인’, 승차 시각만 있으면 ◆ 표식(‘하차 미기록’), 시각이 전혀 없으면 그래프 아래 ‘시각 미기록’ 목록, 승·하차 시각이 같으면 0분 표식, 자정을 넘기면 다음 날 연장 구간, 탑승 중이면 현재 시각까지 잠정 구간, 놓침·관찰은 속이 빈 표식(탑승 통계 제외).
- `24시간 전체` / `이동 시간대` 보기, 확대·축소·좌우 이동 버튼(터치 스크롤 가능), 막대를 누르면 시각·노선·역·좌석 상태와 수정 화면 링크가 나옵니다. 수정 후에는 보던 화면으로 돌아옵니다.
- 아래 ‘하루 요약’은 계산 가능한 건수와 함께 탑승 수, 지하철/버스 수, 탑승 시간 합계, 확인된 서서/앉아서 시간, 최초 착석·중간 착석 수를 보여 줍니다(등·하교 전체 이동 시간과는 다른 값).

### 고급 검색 (캘린더 → 검색·목록)

- **키워드**: 공백·대소문자 무시, 여러 단어는 모두 일치(AND), `수원`≈`수원역`, 동의어(앉음/착석/앉아서, 서서/기립), `10-3`(칸-문)·`10칸`·`2번째`, 날짜(`2026-03`, `3월2일`), 시각(`08:30`), 좌석 이벤트의 역·시각·메모까지 검색합니다.
- **상세 조건**: 기간(빠른 선택/직접), 요일, 승·하차 시각 범위(자정을 넘는 범위 지원), 소요 시간, 노선·승하차역·행선지·출발지, 칸·문·좌우·대기 순서, 좌석(처음부터 앉아서/서서/중간 착석/끝까지 서 있었음 확인/최종 상태/미확인), 혼잡도, 지연, 교통수단·종류·목적. 조건 사이는 AND, 한 조건의 여러 값은 OR. 자동 완성은 저장된 기록에서 나온 값만 제안합니다.
- **결과**: 날짜별 묶음, 일치 항목 강조, 최신/오래된/소요 시간 정렬(시간을 모르는 기록은 항상 뒤), 30건씩 ‘더 보기’, 상세에서 돌아와도 조건·스크롤 유지, 조건 초기화.
- **결과 통계**: 통계 화면과 같은 함수·정의로 즉시/한 번이라도 착석률, 평균 탑승 시간, 착석까지 평균, 혼잡도 분포를 계산하고 표본 수와 ‘표본 부족’을 함께 표시합니다. 시각·좌석이 없는 기록은 해당 지표에서 제외합니다.
- 검색 조건은 이 탭(세션)에만 임시 보관하며 데이터베이스나 백업에 들어가지 않습니다.

### 기록 종류와 입력 항목

- 종류: **탑승**, **놓침·탑승 실패**, **관찰만** — 탑승하지 않은 기록은 이동 횟수·착석률에서 제외됩니다.
- 지하철: 노선, 열차 출발지·행선지, 급행/일반, 승·하차역과 시각, 칸·문(예: 10-3), 좌/우/양쪽/미상, 대기 순서, 좌석 상태, 혼잡도, 지연·특이사항, 비고
- 버스: 버스 번호, 승·하차 정류장과 시각, 앞문/중문/뒷문, 대기 순서, 좌석 상태, 혼잡도, 비고 (지하철 전용 필드를 요구하지 않음)
- **좌석 변화 이벤트**: 한 번의 탑승에서 `08:24 서서 탑승 → 08:30 ○○역 착석 → 09:20 하차`처럼 상태가 바뀔 수 있습니다.

### 빠른 기록의 입력 구성

위에서 아래로 **교통수단 → 노선 → 승차역 → 하차역 → 열차 운행 출발지·종착역 → 탑승 시각 → 위치(칸·문·좌우·대기) → 좌석 → 중간 착석 → 혼잡도·비고 → 저장** 순서입니다. 자주 타는 경로 칩을 누르면 대부분이 한 번에 채워지고, 상세 항목은 필요할 때 펼칩니다.

- **노선**: `수인분당선` · `1호선` · `2호선` 토글 버튼이 먼저, 그 밖의 노선은 `기타`에서 검색·직접 입력(버스는 번호 입력). 노선을 고르는 것만으로는 아무것도 저장되지 않습니다.
- **승·하차역**: 노선별 추천 칩(수인분당선 오목천·수원·고색 / 1호선 수원·신도림·구로 / 2호선 신도림·홍대입구·합정). 하차역은 선택한 승차역에서 자주 내린 역을 먼저 추천합니다. 추천에 없는 역은 검색하거나 직접 입력할 수 있고, `수원`처럼 줄여 쓴 이름은 이미 쓰는 표기(`수원역`)로 통일됩니다.
- **열차 운행 출발지·종착역**: 타는 역과 별개로 각각 고릅니다(`서동탄 → 광운대행`). 수인분당선은 인천·왕십리, 1호선은 서동탄·천안·신창·청량리·구로, 2호선은 성수·신도림·까치산을 추천하고 기록에서 자주 쓴 값(광운대·병점·동묘앞 등)도 이어서 추천합니다. `성수 → 성수` 같은 순환 운행도 허용하며, 모르면 비우거나 한쪽만 입력할 수 있습니다.
- **중간 착석**: `서서 탑승`을 고르면 `+ 중간에 앉음 기록`이 나타납니다(시각·역·비고, 모두 선택). 실시간에는 `지금 앉음`으로 현재 시각이 들어갑니다. 이 입력은 첫 번째 착석 이벤트 *하나*를 만들거나 고치므로 눌러도 이벤트가 중복되지 않고, 여러 번 바뀌는 경우는 탑승 중 `앉았다`/`일어섰다` 버튼이나 기록 수정의 `좌석 변화 추가`를 씁니다.
- **탑승 중 좌석 변화 수정·삭제**: 탑승 중 화면의 `17:30 · 착석` 같은 각 항목에서 `수정`(상태·시각·역·비고)과 `삭제`(그 이벤트 하나만)를 바로 할 수 있고, 변경 직후 `실행 취소`로 되돌릴 수 있습니다. 현재 좌석·첫 착석까지의 시간은 이벤트 목록에서 항상 다시 계산되어 마지막 이벤트를 지우면 그 이전 상태(없으면 탑승 시 좌석)로 돌아갑니다. 같은 분의 서로 다른 이벤트(착석→일어섬)는 합치지 않고 입력 순서·식별자를 유지하며, 현재 상태와 같은 버튼을 연타해도 이벤트가 중복되지 않습니다. 이벤트의 상태·시각·개수나 탑승 시 좌석이 바뀌면 `좌석 변화 기록 완결` 확인은 자동으로 해제되어(다시 확인 필요) 이전 확인이 부정확하게 남지 않습니다.
- **시각 입력**: 모바일에서 잘리지 않도록 `오전/오후` 버튼과 `시`·`분` 선택을 한 행 전체 너비로 분리했습니다(320~390px, 글자 크기 확대에서도 줄바꿈). 저장 형식은 기존과 같은 24시간제 `HH:mm`입니다.
- 점선 칩은 **추천**이고 눌러야 입력됩니다. 좌석 상태·혼잡도·착석 시각 같은 관측값은 과거 기록으로 채우지 않습니다.
- 노선별 추천 목록은 [`src/domain/stations.ts`](src/domain/stations.ts) 한 곳에 있어, 다른 노선이나 역을 쓰려면 그 표만 고치면 됩니다.

## 설계 원칙 (데이터를 정직하게 다루기)

1. **모르는 값은 `null`(미기록)** 로 저장합니다. 다른 기록으로 추정해 채우지 않습니다.
2. **미기록과 해당 없음을 구분**합니다. 값이 없어도 `해당 없음`으로 체크한 필드는 `naFields`에 기록됩니다(CSV에서는 빈 칸=미기록, `N/A`=해당 없음).
3. 승차 시각만 있으면 하차 시각과 소요 시간은 비워 둡니다. 좌석 정보가 없으면 '서서 감'으로 단정하지 않습니다.
4. **실제 입력값과 추천값을 구분**합니다. 추천은 점선 칩으로 표시되고, 누르기 전에는 저장되지 않으며, 좌석 상태·혼잡도·대기 순서 같은 **현재 관측값은 추천하지 않습니다.** 이전 기록을 복사해도 장소·행선지·위치만 가져옵니다.
5. 통계는 값이 있는 기록만 표본으로 쓰고, **모든 비율에 분자/분모와 판정 가능한 표본 수**를 함께 표시합니다.

### 착석 지표 정의

| 지표 | 정의 | 분모 |
| --- | --- | --- |
| 즉시 착석률 | 탑승 시점에 앉아 있었음 | 탑승 시 좌석이 기록된 탑승 |
| 한 번이라도 착석 | 탑승 중 한 번이라도 앉음 | 앉은 기록 + '끝까지 서 있었음(변화 없음)'이 확인된 기록 |
| 최종 착석률 | 하차 직전 앉아 있음 | 좌석 변화 기록이 **완결**(`seatLogComplete`)로 확인된 탑승 |
| 서서 탄 뒤 착석까지 | 서서 탑승 → 첫 착석까지 분 | 두 시각이 모두 있는 탑승 |
| 서서 이동한 시간 | 서 있던 구간의 합 | 변화 기록 완결 + 승·하차·변화 시각이 모두 있는 탑승 |

통계 화면은 지표마다 **판정 가능 건수와 제외 건수·제외 이유**를 숫자보다 먼저 보여 주고, 판정 표본이 10건 미만이면 `표본 부족 — 해석 주의`, 전체의 절반 미만만 판정되면 `전체의 N%만 판정 — 전체 착석률로 읽지 마세요`를 표시합니다. 서서 탔지만 이후를 확인하지 않은 기록은 `서서 감`도 `앉아서 감`도 아닌 미확인이라 `한 번이라도 착석` 분모에서 빠지므로, 그 비율이 100%로 높게 나와도 전체 착석률이 아닙니다(기록 수정에서 좌석 변화를 확인하면 표본이 늘어납니다).

자정을 넘기는 이동(23:50 → 00:10)은 다음 날로 계산합니다. 필요한 시각이 하나라도 없으면 계산값도 미확인으로 남깁니다.

`main` 브랜치에 push 하면 GitHub Actions(`.github/workflows/ci-deploy.yml`)가 다음을 순서대로 실행하고, **모두 통과해야만** `https://oyueo-mm.github.io/TransitLog/` 에 배포합니다.

1. 개인정보 검사(`scripts/check-privacy.mjs`: 개인 데이터 파일이 저장소·이력·산출물에 없는지)
2. 타입 검사 · 린트 · 단위 테스트(Vitest) · 빌드
3. 브라우저 테스트(Playwright: 360px 모바일·데스크톱, PWA 설치 가능성, 오프라인, 백업·복원, 이관)

- 앱은 `base: '/TransitLog/'`, 매니페스트 `start_url`/`scope`/`id` = `/TransitLog/`, 서비스 워커 범위 = `/TransitLog/` 로 빌드됩니다. 다른 경로에 올리려면 `VITE_BASE=/경로/ npm run build`.
- 라우팅은 HashRouter(`#/quick` 등)라 정적 호스팅에서 새로고침해도 404가 나지 않습니다.
- 배포된 실제 주소를 검증하려면: `E2E_BASE_URL=https://oyueo-mm.github.io/TransitLog/ npx playwright test` (테스트는 임시 브라우저에서 돌아 내 기록에 영향을 주지 않습니다).
- **앱을 업데이트해도 저장된 기록은 지워지지 않습니다.** 서비스 워커 캐시와 IndexedDB 는 별개이며, 스키마 변경은 Dexie `version()` 업그레이드로만 처리합니다(`tests/schema-compat.test.ts` 가 v1 데이터 호환을 검사).

## 데이터 보관 방식

IndexedDB(`TransitLog`)에 용도별로 분리해 저장합니다.

| 테이블 | 내용 |
| --- | --- |
| `trips` | 탑승·놓침·관찰 기록 |
| `seatEvents` | 한 번의 탑승 중 좌석 상태 변화 (`tripId` 로 연결) |
| `days` | 날짜별 일지 (집 출발·학교 도착·학교 출발·귀가) |
| `templates` | 직접 저장한 경로 템플릿 |
| `settings` | 마지막 사용값, 마지막 백업 시각 등 |

- 스키마 버전은 Dexie `version()` 과 백업 파일의 `schemaVersion` 으로 관리합니다. 더 새로운 버전의 백업은 거부하고, 이전 버전 백업은 읽을 때 현재 형태로 올립니다.
- 브라우저 데이터 삭제·기기 변경으로 기록을 잃지 않도록 **JSON 백업을 정기적으로** 받아 두세요. 복원은 기본이 **병합**(같은 기록은 건너뛰고 기존 데이터를 덮어쓰지 않음)이며, 전체 교체 복원은 현재 데이터를 먼저 자동으로 내려받은 뒤 진행합니다.
- 착석 가능성 예측을 나중에 붙일 수 있도록 `src/domain/features.ts` 에 특징(feature)·라벨(label) 평면 데이터셋 변환을 마련해 두었습니다. 지금은 단순 통계만 제공합니다.

## 기존 노트(Samsung Notes) 가져오기

설정·백업 → **PDF 가져오기** (또는 `#/import`).

1. PDF 에서 **텍스트를 추출**합니다 (pdf.js). 줄바꿈으로 갈라진 문장은 이어 붙이되, 날짜·머리줄·상세 줄은 붙이지 않습니다. 텍스트가 없는 PDF(손글씨·이미지)는 OCR 을 지원하지 않으므로 안내만 합니다. PDF 안의 사진은 읽지 않습니다.
2. 날짜·이동 기록 단위로 나누고 노선(또는 버스 번호), 출발→종착, 승·하차 구간과 시각, 칸-문, 좌우, 대기 순서, `서서감->○○역에서 앉음(08:30)` 같은 좌석 변화, 하루 단위 기록(`(07:55 집에서 출발)`)을 읽습니다.
3. `??`·`?`·`기억 안 남` 은 값으로 채우지 않고 미기록으로 둡니다. `4?5번째`·`~듯` 같은 불확실한 서술도 값으로 확정하지 않고 비고/검토 사유로 남깁니다.
4. 비고는 **순화**합니다 — 욕설·감정 표현은 중립 문장으로("사람 개많음" → "승차 당시 매우 혼잡했음"), 교통과 무관한 개인 이야기와 다른 승객의 신상·외모 묘사는 제외하고 교통 사실(지연·혼잡·좌석·대기)은 보존합니다. 제외한 문장은 미리보기에서 사유와 함께 보여 줍니다.
5. 탑승 근거가 없으면 **관찰만**, 못 탄 기록은 **놓침**으로 분리하고 검토 대상으로 표시합니다.
6. 이미 저장된 기록(날짜·종류·시각·노선·장소가 같음)은 **중복**으로 표시되어 건너뜁니다.
7. 요약(전체 후보·확정·검토 필요·누락 정보) → 원문/변환 결과 비교·수정 → **승인한 것만 저장**. 원문은 저장하지 않고 정제된 데이터만 저장합니다.

미리보기의 *일괄 적용*(자동 적용 안 함): ① `서서감`/`앉아서감`만 적힌 기록을 "탑승 중 변화 없음"으로 확정, ② 집 출발·학교 도착 시각 기준 등·하교 구분 추천.

### 개인 단어 제외

가져오기 화면의 **제외할 개인 단어**에 약속·일정 같은 단어를 적어 두면, 그 단어가 든 비고 문장은 가져오지 않습니다(운행 지연·사고 정보는 예외). 입력한 단어는 **이 기기의 브라우저에만** 저장되며 저장소·서버에는 올라가지 않습니다. 로컬 스크립트는 `private/exclude-words.txt`(한 줄에 한 단어)를 읽습니다.

### 개인 기록 취급

- **원본 PDF, 변환된 실제 기록, 백업 파일은 절대 공개 저장소에 올리지 않습니다.** `.gitignore` 가 `*.pdf`, `private/`, `transitlog-backup-*.json`, `transitlog-*.csv` 를 제외하고, `npm run check:privacy` 가 추적 파일·Git 이력·빌드 산출물에 개인 데이터가 없는지 검사합니다(CI 에서도 실행).
- 로컬에서는 `private/denylist.txt`(실제 역 이름·메모 목록, 저장소에 없음)를 만들어 두면 같은 검사가 그 문자열까지 대조합니다.
- 테스트와 픽스처는 모두 **가상의 데이터**입니다. 실제 기록을 넣지 마세요.
- 로컬 변환 스크립트(`npm run import:local -- <노트.pdf> --out private/x.json --confirmed-only`)는 결과를 `private/` 에만 씁니다. 만들어진 JSON 은 설정·백업 → 복원으로 불러옵니다.

## 알려진 한계

- 노트 파서는 규칙 기반입니다. 실제 노트 형식에 맞춰 만들었지만 새로운 표기에서는 "검토 필요"나 `해석하지 못한 줄`로 남을 수 있어 미리보기 확인이 필요합니다. 비고 순화도 완벽하지 않으니 원문과 비교해 주세요.
- OCR(손글씨·이미지 PDF)과 PDF 속 사진은 지원하지 않습니다.
- 클라우드 동기화가 없어 기기 간 이동은 백업 파일로 합니다(기기마다 기록이 따로 저장됩니다). iOS 는 고려하지 않았습니다.
- 설치·오프라인 동작은 Chromium 기반 자동 테스트로 검증했습니다. 실제 Android 기기에서의 설치 UI는 직접 확인해 주세요.
- 예측 기능은 구조만 준비했고 구현하지 않았습니다.
- 타임라인: 좌석 변화 기록 완결이 확인되지 않은 탑승의 마지막 변화 이후 구간은 ‘미확인’으로 표시합니다(실제로는 앉아 있었을 수 있지만 추정하지 않음). 24시간 전체 보기에서는 짧은 탑승 막대가 작게 보이므로 ‘이동 시간대’ 보기나 확대를 쓰세요.
- 검색: 동의어·표기 정규화는 규칙 기반이며(`수원`≈`수원역`), 비슷한 다른 역 이름(예: 접두어가 같은 역)도 부분 일치로 함께 나올 수 있습니다.
